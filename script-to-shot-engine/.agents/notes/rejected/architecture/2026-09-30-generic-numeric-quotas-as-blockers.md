# Agent Note: 通用数值配额不得作为阻断级约束

Status: rejected

## Proposal

把下面四条作为 `structural_invariant`，由脚本阻断交付：

- 只交代场面信息的无台词镜头总时长 ≤3 秒
- 承载剧情变化的无台词镜头，一段里 ≤2 个
- 单个说话人镜不得超过本 Clip 时长的一半
- 分镜时长不得超过「台词时长＋已写动作所需」的约 2 倍

## Alternatives considered

**全部作为阻断级约束** —— 最强理由：这些数值来自真实实测（每插一个纯动作无台词镜头，后面台词整体推后 0.3—0.9 秒），可测量、可自动检查，能立刻压掉"15 秒里什么都没发生"这类问题，而且它们确实是在两轮实测里被证明有用的。

**不采用**：它们是**跨项目通用的配额**，与具体项目的动作预算和创作者权威冲突。反例来自本技能自己的实测样片：15 秒里 5 秒的无台词发现段（她看见鞋带 → 蹲下系鞋带）是整场的转折点，按配额会被判违规——**规则会误杀它本来要保护的东西**。同类做法在参照实现里也被否决：通用节拍、字数、反应镜配额「与项目的动作预算和创作者权威冲突，数值只作为项目档案」。

## Decision（现在时）

这四条分别降为：

- `DEN-01`／`DEN-02`／`DEN-03`（`craft_default`）——数值保留为**倾向**，措辞明确标注"不是硬阈值"；超了说明理由即可，不阻断。
- `TAS-01`（`reviewed_invariant`）——只有「是否在镜内写明了理由」交审查者，不看数值本身。

通用数值改由**项目档案**承载（`max_shot_seconds`、`aspect_ratio` 等），脚本按 `PRJ-01` 校验"是否等于创作者已接受的值"。

## Consequences

- **收益**：正当的无台词戏剧段落不再被误杀；创作者一句理由即可覆盖；硬约束减少 4 条；同类问题以后走"记进项目档案"，不再新增规则。
- **代价**：失去一个廉价的数量兜底，密度问题重新依赖审查者的判断与创作者的自觉。如果实测证明没有配额就普遍失控，需要重新评估——但那时应该改的是**默认值**或**项目档案模板**，不是恢复全局硬阈值。
