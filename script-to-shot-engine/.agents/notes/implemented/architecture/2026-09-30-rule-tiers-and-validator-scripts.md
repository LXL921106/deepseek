# Agent Note: 规则四级分级与校验脚本边界

Status: implemented

## Problem

技能在 6 个版本里积累到 **261 条**规则性条目、**37 条**最终检查、渲染器文档从 14,015 涨到 28,752 字节——但实测仍在反复漏台词。

根因不是措辞，是**结构**：所有规则处在同一约束力层级，模型无法区分「违反就废片」和「建议如此」，于是随机丢。检查项是散文反问（「都出现了吗？」），**是否真的核对过，在交付物上看不出区别**。

## Decision

每条规则归入四级之一，登记在 `references/rule-tiers.md`，并绑定判定者：

| 级别 | 判定者 | 能否阻断 |
|---|---|---|
| `structural_invariant` | **脚本** | ✅ 能 |
| `reviewed_invariant` | 审查者引用证据 | 需证据 |
| `craft_default` | 创作者，说明理由即可覆盖 | ❌ |
| `taste_option` | 创作者 | ❌ 不得单独阻断 |

分工：能算的交给 `scripts/` 下的 Python 校验器；要判断的交给审查者；可选的交给创作者。`SKILL.md` 的最终检查与 `wan-renderer.md` 的 34 条清单**都改为三层门禁**。

通用数值（时长、字数、镜头数、比例）不再是硬约束，改为进**项目档案**；脚本只能校验「是否等于创作者已接受的值」（`PRJ-01`）。

## Alternatives considered

- **继续加禁令 + 加检查项** —— 最强理由：改动最小，每发现一个真实缺陷就立刻堵上，历史证明它确实堵住过空镜与「动作做完再说话」。不采用：6 个版本里每加一条"必须"，都在别处开一个新洞（`并行` 被推广成"同一镜内堆所有人动作"；`信息密度配额` 误杀了正当的无台词戏剧段），并且规则数增长到 37 条自查时**等于没有自查**。
- **只把规则写得更清楚、更详细** —— 最强理由：不需要新机制，纯写作改进，可移植。不采用：反复出现的漏台词发生在规则措辞**已经正确**的情况下；问题不在措辞，在没有可核对物。
- **只保留散文规则，不做脚本** —— 最强理由：跨平台、无依赖。不采用：「台词是否漏了」是逐字比对，属本地可证明；交给语言判断既浪费也不可靠。

## Consequences

- **收益**：谁能判、能不能阻断一目了然；漏台词／残句／时间戳断裂第一次变成**可自动阻断**；`SKILL.md` 降到 240 行（官方建议上限 500 行），禁令词从 56 次降到 22 次。
- **代价与已知上限**：语义规则仍靠审查者，覆盖率低于脚本；`AST-01`、`FMT-01`、`PRJ-01` 尚未实现校验器；脚本对剧本与交付物格式有约定（`名字：台词`、`人物名（语速）："台词"`），格式变了脚本会失效——那属于 `reviewed_invariant`，需人工确认。
