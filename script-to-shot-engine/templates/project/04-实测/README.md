# 04-实测

**实测是唯一的真凭据。** 提示词写得对不对，最终看片子。

每测一段，留一行：

| 组 | 提示词写的台词区间 | 实测台词区间 | 偏差 | 无台词尾段 | 语音电平 | 结论 |
|---|---|---|---|---|---|---|

## 测什么（用 `scripts/check_groups.py`）

| 指标 | 怎么来 | 看什么 |
|---|---|---|
| 时长／分辨率／帧率 | `ffprobe` | 有没有被平台改 |
| 台词实际起止 | `silencedetect` | **和提示词写的时间戳差多少** |
| 尾段电平 | `volumedetect` | 是"写了无台词"还是"被截断" |
| 抽帧接触表 | `fps=1` + `tile` | 口型、姿势、站位是否按写的走 |

## 与上一轮对照

**每次都要比：这一轮是新问题，还是老问题复现？** 没有对照就没有"进步/退步"。

结论分三类落到 `05-复盘/`：

- **规则错了** → 改技能，并加一个能证伪它的夹具
- **规则没错但没被执行** → 是门禁的缺口（要做成脚本）
- **创作者偏好变了** → 改 `01-档案/项目档案.md`，**不要改技能**

---

## ⚠️ 改之前先判断：结构性失败，还是随机波动

**这类视频的接受率很低（业界约 1.5%）。大多数失败是随机波动，不是提示词坏了。**

| 问自己 | 结论 | 怎么做 |
|---|---|---|
| 每次**都**以同一种方式失败？（身份每次都飘、服装每次都串、镜数每次都不对） | **结构性**：提示词真错了 | 改提示词，**且一次只改一个变量** |
| 失败方式**各不相同**，偶尔还有接近的？（这次表情平、上次机位歪、下次物理怪） | **随机**：提示词是对的，只是这一把骰子不好 | **锁住提示词，批量出片，然后挑一条** |

**判错的代价**：对着随机波动去单条改提示词，是在**修一个本来就对的提示词** —— 白烧钱，还会把对的改坏。

### 样本不够就别下结论

**记录少于 5 条时，上面这个分类本身就是噪音。** 停手，用眼睛判断，**不要动基线**。

> 教训：我们曾拿 **2 次实测** 就改了语速基线，随后被创作者否掉。2 条记录分不出"结构性"和"随机"。
